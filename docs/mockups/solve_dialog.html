Stability gets its own alpha

Today the stability run silently reuses alpha_start_deg, the start of the sweep range. That is why yours ran at −5°. Here it is a separate field, so the sweep can cover −4…12 while the derivatives are taken at trim.

The trim warning is live

The dialog knows the speed and the mass, so it can compute the trim incidence before you spend two minutes. The button copies it into the alpha field.

Thin or thick, stated

thick exists in the schema and reaches no UI at all today. It is the closest thing to "which kind of sweep": thin is vortex lattice, thick is panels and the only one that gives a fuselage.

Cost before commitment

Angle count times fidelity is a number the app already knows. Showing it turns "is this frozen?" into "this takes two minutes".

Blank means inherited

Reference values show what the wing would supply, greyed. You can see the number without overriding it, and typing replaces it.

Speed sweep costs one solve

Lift equals weight, so each speed fixes its own CL. The induced drag comes from the existing polar; the profile drag is re-integrated at that speed's Reynolds. Out comes best range and best endurance — and the second is always the slower of the two.

CG sweep costs nothing

The neutral point does not move when the mass does, so one stability run gives the whole curve of SM = (X_np − x)/cref and the modes at every position. It reports the conventional band and a recommendation — and says that Cm_q is held, so the margin stays exact while the damping degrades away from the solved CG.

What is not here

Control deflections. They are in the schema and no solver reads them yet, so a field would promise something that does nothing. Mode animation is not here either — it belongs beside the modes, so it is a button on the Dynamics screen rather than a run to configure.
